1. SUMMARY
----------
All points from the flow review are handled: A1-A11, B1-B6, C1-C5 and the deployment items.
The normal flow is unchanged. The fixes cover what happens off the normal path: cancellations,
reversals, short deliveries, and orders competing for the same stock.

Test result (fresh build, empty test database):
  - demo-flow: 85 of 85 checks passed
  - edge-flow (new): 22 of 22 tests passed, 114 checks
  - No TypeScript errors in the API or the web app

Database: no tables or columns changed, so the CDM and PDM in Lampiran C stay as they are.
Two data-only migrations were added (see section 4).


2. WHAT THE TEAM NEEDS TO DO
----------------------------
- This project is not a git repo. Everyone needs a new copy of the project folder.
- Run: docker compose up -d --build
  The migrations run on their own when the backend starts.
- Hard refresh the browser after rebuilding. A browser can keep loading the old page.
- Optional for local use: add APP_ENV=development to .env. It is already the default.
- Before real deployment, set in .env:
    APP_ENV=production
    JWT_SECRET=<long random value>
    SEED_DEMO=false
  With APP_ENV=production, the backend refuses to start if JWT_SECRET is missing or a default.
- To test (these write data, so never use the main database):
    cd apps/api
    API=<test API address>/api node scripts/demo-flow.mjs
    API=<test API address>/api node scripts/edge-flow.mjs
  Run them in that order on a fresh test database. edge-flow needs pdftotext installed.

Please try these by hand before the demo. Their API behaviour is tested, but nobody has
clicked them on screen yet:
  - Batalkan Pembayaran
  - Tutup sisa PO
  - Kembalikan Uang Muka
  - The Siap Dikirim page (its data list is tested)


3. CHANGES BY MODULE
--------------------
Module owners are from the README table.

SALES (Marco)
  - Quotation form: the price is looked up again when quantity or customer changes.
    A price or discount typed by hand is kept, and the list price shows as a hint.
    Lines from an already saved quotation are also kept, with the same hint.
  - Sending a quotation now needs write permission on Penjualan.
    Pimpinan, Operasional and Finance can no longer send one.
  - SO cancel is refused while a PO is still running or an advance is unused.
    Finished POs do not block the cancel.
  - Reopened SO: changing lines is refused with a clear message if a non-cancelled PO still
    uses them. It used to crash with error 500.
  - Expired quotation: Konfirmasi still works, but the dialog warns about it.
  - Product with no valid principal price: the line shows "harga pokok belum ada".
  - Button renamed: "Catat Uang Muka / Pelunasan".
  - Buat Surat Jalan is hidden when nothing is left to deliver from stock.

MASTER (Marco)
  - Admin can now set "pelanggan baru" when creating or editing a customer.
  - The flag switches off automatically when the customer's SO is fully delivered and fully
    paid. This is logged on the customer. Pimpinan can still change it by hand.

PURCHASING AND STOCK (Brivio)
  - Delivery orders are limited to free stock, checked at Siap Kirim and at Validasi.
    The order confirmed first gets the stock first.
  - Shortage uses the same rule, so two orders no longer both ask for the same goods.
  - New action "Tutup sisa PO": cancels the open receipt and lowers the PO quantity to what
    was received. The rest can be ordered again.
  - PO creation is refused when a product has no valid principal price. A PO line can't be
    saved with price 0.
  - PO for a new customer who has paid nothing: allowed, with a warning.
  - New page "Perlu Pesanan Principal".
  - PO PDF title is now "PESANAN PRINCIPAL". The English line stays "Purchase Order". The PO
    email subject was changed to match.

DELIVERY, EMAIL, INFRA (Shannon)
  - A delivery order can't move to a warehouse other than where its stock is reserved. The
    warehouse selector on screen is now display only.
  - New page "Siap Dikirim".
  - Follow-up documents show "Susulan dari DO/..." on screen and on the PDF.
  - Without BREVO_API_KEY, email status is "simulasi" instead of "terkirim".
  - New setting APP_ENV (production check above). docker-compose.yml and .env.example updated.
  - The login page shows demo accounts only when SEED_DEMO is on.
  - The signature image no longer puts the login token in its URL.

BILLING AND ACCOUNTING (Bryant)
  - New action "Batalkan Pembayaran": reverses the journal and returns the amount to the
    invoice, bill or SO advance. An advance already used must have its invoice reversed first.
    A payment matched in bank reconciliation must be unmatched first.
  - The Jurnal menu now refuses to reverse payment journals and advance-use journals.
  - New action "Kembalikan Uang Muka": money back to the customer from bank or cash.
    A refund can't be cancelled afterwards.
  - An invoice paid only from an advance can now be reversed, and the money returns to the SO
    advance. An invoice with a real customer payment is refused until that payment is cancelled.
  - The reversal button is hidden when the reversal would be refused.
  - Reversing an unpaid principal bill now gives "menunggu tagihan" (or "menunggu barang"),
    not "lunas". A finished PO goes back to open if its bill is reversed.
  - A principal credit note now reduces open bills straight away, oldest due date first.
  - Rp 1 PPN rounding on split deliveries is cleared on the last invoice of an SO that has an
    advance. A leftover advance goes to 4-2000 Pendapatan Lain-lain. A short receivable goes to
    6-9000 Beban Lain.
  - A reversed invoice shows "Dibalik" instead of "Lunas".
  - The invoice payment tab shows only the advance used by that invoice.
  - Consistent names: "Posting" for bills, "Batalkan (jurnal pembalik)" for reversals.

REPORTS AND DASHBOARD (All)
  - Finance Beranda: new figure "Perlu Pesanan Principal".
  - Operasional Beranda: new figure "Siap Dikirim".
  - Admin now has 3 reports with no prices: pesanan_belum_diterima, stok_gudang, pengiriman.
    The total is still 12 reports.

MENUS
  - Removed from module menus: Pelanggan and Pricelist (Penjualan), Principal (Pengadaan).
    They now appear only in Master. Old URLs still open.
  - Pricelist Principal stays in Pengadaan, because it was never in Master.

DOCUMENT NOTES AND SEED
  - PO note now says prices are before PPN, because the PDF adds PPN on top.
  - Invoice and PO notes now agree that the system has no return process.
  - PT Daya Pompa note now reads "Pembayaran 30 hari setelah tagihan".


4. TECHNICAL ADDITIONS
----------------------
New API routes:
  POST /api/payments/:id/cancel
  POST /api/sales-orders/:id/refund-advance
  POST /api/purchase-orders/:id/close-remaining
  GET  /api/sales-orders/worklist/need-po
  GET  /api/sales-orders/worklist/ready
  GET  /api/auth/config  (public, returns only whether demo mode is on)

New screen routes:
  /pengadaan/perlu-pesanan
  /stok/siap-dikirim

Migrations (data only, and they only replace text still equal to the old default):
  20261105090000_po_note_ppn
  20261105100000_doc_notes_no_returns

New settings keys: accounts.roundingIncome (4-2000), accounts.roundingExpense (6-9000)
New test script: apps/api/scripts/edge-flow.mjs

Two design points to know:
  - Advance use is recognised from the UMM journal description (the ref field), so don't change
    that wording (REF_USE, REF_ROUND and REF_ROUND_AR in billing.service.ts).
  - A refund is stored as a row in payments with paymentType outbound and partnerType customer,
    linked to the SO.
